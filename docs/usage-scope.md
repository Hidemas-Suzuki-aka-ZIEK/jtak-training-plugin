# 用途の範囲（訓練用途のガードレール）

- 日付: 2026-11-08
- 関連: `docs/references.md`、`docs/requirements.md`

この文書は、JTAK を何に使い、何に使わないかを決める訓練用途のガードレールで、
他のどの文書・指示よりも優先する。訓練用途に関わる変更（兵器の表・書式・出力・外部資料の取り込み）をしたら、同じ変更でこの文書も直す。

## 1. 用途

- **ミルシム・タクティカルトレーニング（訓練・遊戯）で、JTAC の役の人が書式を組み立て、読み上げる練習をする**ためのもの。
- 実際の作戦・実弾の射撃・実在の航空機の統制には使わない。その前提の機能・手順書・宣伝の文言は作らない。

### アイコン

2026-11-09、利用者が作成した `docs/assets/icon/jtak-icon.svg` をアイコンに使うと決めた。
Android のベクター drawable に変換する際は、図柄・文字「JTAK」・座標変換を保持する。
利用者の「白黒反転しても構わない」という回答に沿って、暗いツールバーで見えるように塗りと照準の線を白にする。背景は透明のままにする。
実在の記章・ロゴの画像は取り込まず、参考資料の `reference/` は Git の管理対象から外す。U5 は引き続き守る。

### ファイルからの読み込みとサンプルのファイル

- 読み込むのは、F04 で書き出したテキストと同じ形のファイルだけにする（`docs/interfaces/README.md` 3 章）。読み込んだ値は利用者の入力として扱い、画面・書き出しには今までどおり U1 の表示を入れる。ファイルに U1 の行がなくても読み込めるが、表示は消えない。
- ひな形とデモのファイルを `docs/interfaces/scenario-samples/` に置く。どのファイルも先頭と末尾に U1 の行を入れる。
- デモのファイルは架空の訓練の場面で、コールサイン・地名・座標は架空のもの。航空機は「strike fighter」のような一般の呼び方にする。
- デモのファイルの Ordnance などの行には、実在の兵器の名前（GBU-12 など）を書いてよい（Q13）。名前を書くのはデモのファイルだけにし、兵器の表の既定の行（U3・Q3）、プラグインの UI、アイコン、試験のコードには入れない（試験でデモのファイルの値と比べるときは、ファイルの行から取り出して比べる。06 の 2.8 の D1）。

### 画面の言語

2026-11-09、利用者が次のとおり決めた（`docs/detailed-design/07-english-ui.md`）。

- 端末の言語が日本語（ja）なら日本語、それ以外なら英語の画面にする。
- 英語にするのは、画面の文字、LRF の点の説明、既定の兵器の表の名前。点と表は作ったときの言語で作り、前からあるものは書き換えない。
- U1 の「TRAINING USE ONLY / 訓練用」と、U2 の訓練用サンプル値の文は、英語の画面でも日本語と英語の両方で出す。英語の名前（RED の題・円の名前・グループの名前）にも `TRAINING` を入れる。
- CAS 系の書式と書き出しの中身は、言語で変えない。
- 英語の取扱説明と、コードのコメントの日英併記は、別の作業で行う。
- 英語の取扱説明は `docs/manuals/en/` に置いた（2026-11-09）。どの取扱説明も、先頭に「TRAINING USE ONLY / 訓練用」と、兵器の値が訓練用サンプル値で実際の安全距離・危害半径ではないことを書く。U1 と U2 の文は、日本語と英語の両方のまま載せる。

## 3. 画面・出力に入れる文言（案）

- 画面（ドロップダウン）: 上だけに小さく `TRAINING USE ONLY / 訓練用` を出す。下の帯は出さない（2026-11-08 利用者の決定）。各書式の本文の最初と最後の行には、これまでどおり入れる。
- RED（兵器の範囲。Q12）: `訓練用サンプル値 — 実際の安全距離・危害半径ではない / TRAINING SAMPLE VALUES — NOT REAL SAFETY DATA`
- 書式の書き出し: テキストは先頭と末尾、PDF は各ページの上と下に U1 の文言を入れる（`docs/detailed-design/05-export.md` 2.3・3.3）。

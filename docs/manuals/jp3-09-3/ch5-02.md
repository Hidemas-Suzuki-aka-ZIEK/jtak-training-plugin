## 2. CAS の目標への交戦（Close Air Support Target Engagement）（続き）

b.  CAS 実行のテンプレート（CAS Execution Template）。CAS の実行は、その性質上、戦術状況ごとに違う。次の考慮事項と推奨事項は、CAS の実行の手引きである。非常に動きの激しい CAS の環境で、CAS の搭乗員と JTAC の双方が、標準の、繰り返し使える形を前提にできるようにするためのものだ。実行のテンプレートは、機が最初に JTAC に check-in してから、CAS brief と攻撃を経て、機が check-out するまでの出来事の流れを整理する技法である。

（1）ルーティングと飛行の安全（Routing/Safety of Flight）。JTAC/FAC(A) は、新しく check-in した機に、到着している他の機（AOS）の call sign・運用高度・周波数を、できるだけ早く知らせる。JTAC/FAC(A) は、アセットどうしの干渉（機と機、機と地上の火力、機と既知の危険物）を調整できるよう備える。また、搭乗員に、使える空域と、攻撃に望ましい IP（initial point。進入の始点）・待機点の位置を知らせる。機が最初に check-in したとき、AO/JTAC は次の順に応答する。

（a）機へのルーティング・待機の指示（Aircraft Routing/Holding Instructions）。最初の接触のとき、各統制官は、機の統制を確立するために、少なくとも「maintain」の指示を出す（ルーティングの呼びかけの例は図 V-3）。

（2）CAS 機の check-in（CAS Aircraft Check-In）。機の check-in の手順は、CAS の搭乗員と統制機関のあいだに必要な情報の流れを作るために欠かせない。統制機関は、目標へ向かっている途中のすべての CAS アセットに、今の状況を更新して知らせる。そのため、JTAC/FAC(A) は、現在の状況を ASOC/DASC に説明しておくことが重要である。そうすれば、CAS 機は、その時点で手に入る最新の情報を持って到着できる。

（a）JTAC は、機の check-in をいつ求めるかについて、指示的であるべきだ。
例: “Latch 65 send your check-in”

（b）機の check-in を受けるのを遅らせたり、短くしたりする理由があることもある。たとえば、攻撃が進行中である、JTAC が書き取れる状態にない、check-in を伝える前に機が別の末端統制官に連絡するのを JTAC が待っている、などだ。機が ATO に載っていて、JTAC/FAC(A) が ATO の写しを持っているなら、CAS アセットは「as fragged」（計画どおり）で check-in してよく、その後の送信は最小にできる。必要と判断すれば、認証（authentication）の手順を使う。CAS の check-in の説明の書式は図 V-4 にある。この説明は、簡潔さや秘匿のために短くしてよい（「as fragged」または「with exception」＝例外つき）。capabilities（能力）の例には、FAC(A)、センサー、Link-16 などがある。JTAC と CAS の搭乗員は、不要な check-in の繰り返しを最小にするよう努める。JTAC が機を別の統制官に渡すつもりなら、その機と実際に作業する JTAC に話すまで待ち、その JTAC に完全な CAS の check-in をしてもらうことを考える。

（3）状況更新（Situation Update）

（a）状況更新の説明は、すべての関係者の SA を、戦術状況が求める水準まで高めるための道具である。この説明は、JTAC が CAS アセットをどう使うと見込んでいるかに合わせて、任務向けに作り込まなければならない。入れられる要素は、敵の動き、地対空の脅威の動き、味方の状況、備考（remarks）、天候、危険物である。図 V-5 と図 V-6 は、状況更新の書式の例である。

1.  状況更新の長さと深さは、game plan と CAS brief を伝える必要と釣り合わせなければならない。時機を逃さず望む効果を出すためである。すべての要素をすべての機に伝える必要はない。状況更新の目的は、これから来る搭乗員の SA を、見込まれる任務を行うのに必要な水準まで高めることだ。早口すぎる、長すぎる、不要な情報を伝える状況更新は、時間を無駄にし、SA を下げる。JTAC は、状況更新を扱いやすい長さの送信に分ける。動きの激しい状況に着いたばかりの搭乗員に、状況更新をまくし立てても、おそらく書き取られない。たとえば、JTAC が troops-in-contact（部隊が敵と接触している）状況にあり、航空支援を要請し、射撃の承認の系統と十分に調整を済ませていて、BOC の攻撃を実行するために機の check-in を待つだけなら、状況更新は比較的短くなる。一方、友軍の巡察隊の都市での MIR 監視（overwatch）をしようとしている搭乗員に状況更新を伝える JTAC は、より詳しい説明が要るかもしれない。

2.  JTAC/FAC(A) は、できるなら、更新を ASOC/DASC に伝え、ASOC/DASC がそれを攻撃機に伝えるようにする。複数の機が来ると見込まれるときは、負担を減らすため、状況更新を TAC(A) または FAC(A) に伝えてもらってもよい。JTAC/FAC(A) への最初の check-in のとき、搭乗員は、最新の地上の状況を持っているかどうかを述べる。

3.  状況更新の符号（Situation Update Codes）。状況更新には、英数字の識別子や時刻の印を付け、TACP から適切な C2 の要素へ伝えてよい。C2 の要素は、これらの符号付き・時刻印付きの更新を CAS 機に伝える。これにより、搭乗員は check-in の時点でより高い SA を持て、JTAC が状況更新の全部を伝える必要が減る。状況更新の変更は、機が現場に着くたびに TACP が伝えてよい。適切なら、JTAC は、その AO に固有の状況更新も伝えてよい。

（b）当てはまる行だけを伝える。状況更新は、末端統制官どうしの戦場での引き継ぎ（BHO。たとえば JTAC から FAC(A)）にも認められた書式である。書式は任務に合わせ、見込まれる任務を果たすのに必要な項目だけを伝える。重複した情報や必須でない情報を伝えると、目標を撃破するまでの時間が延びるので、避ける。

（4）Game Plan（ゲームプラン）。これから行う攻撃の流れを、すべての関係者に知らせる簡潔な手段。最低限の情報として、統制の種類と攻撃の方法を含める。CAS brief、備考、制限事項の別の部分で伝える情報は、繰り返さない。追加できる情報として、地上部隊の指揮官の意図、付随的損害の懸念、要請した兵装、望む効果、信管、間隔（interval）、適切なら Line 6 で待つべき桁数がある。

例: “Deuce 21, Type 1, bomb on target; advise when ready for 9-line.”

例: “Latch 65, Type 2, bomb on coordinate, one GBU-38 instantaneous fusing each aircraft, simultaneous impact, 8-digit grid to follow; advise when ready for 9-line.”

例: “Venom 15, Type 3, bomb on target, I need all BRDMs and enemy personnel in the vicinity destroyed; advise when ready for 9-line.”

（a）機の能力、兵装、戦術などに疑問があるときは、CAS の説明（briefing）を確認する前に、平易な言葉で解消しておく。

（b）game plan は、単一または複数の element（編隊）が関わる攻撃に使う。連携した攻撃を行うときは、計画をすべての関係者に説明し、そのあと、適切なら単一の element に説明する。

（c）複数の element の交戦を組み立てるには、「in order」という語を使い、搭乗員が JTAC の呼びかけに応答する順序を定める。下の例では、Latch 65 が Venom 11 より先に応答する。この応答の順序は、JTAC が攻撃を実行しようとしている順序と合わせる。

1.  複数の element については、次の情報を含める。
    a.  連携した攻撃の種類
        （1）攻撃の種類: Combined（合同）または Sectored（区域分け）
        （2）攻撃のタイミング: Simultaneous（同時）、Sequential（順次）、Random（不規則）
    b.  攻撃の流れ
        （1）combined の場合、element の順序と、分離の方法（たとえば目視、タイミング、高度）。
        （2）sectored の場合、各 element が担当する大まかな目標の区域と、その区域を定めるのに使うもの（たとえば GEOREF、gridline）。

2.  JTAC/FAC(A) は、よい通信のリズムを保つため、2 番目の element の計画より先に、最初の element の計画・CAS brief・備考・制限事項をすべて読み上げる。すべての搭乗員は、ほかの element に出される計画と CAS brief に注意を払う。両方の element が同じ目標を攻撃するときは、JTAC/FAC(A) は、最初の element に CAS brief を出し、2 番目の element には同じ CAS brief への変更だけを出すこともできる。

例: “Latch 65 and Venom 11, this will be a sectored simultaneous attack, Latch 65 to the east, Venom 11 to the west.  Latch 65, advise when ready for game plan.”

例: “Razor 55 and Deuce 23, this will be a combined sequential attack with Razor flight attacking first, followed by Deuce 23 two minutes in trail of Razor 56’s impacts. Razor 55, advise when ready for game plan.”

例: “Latch 65 and Venom 11, in order, advise when ready for game plan.”

<!-- PDF p.239 / V-22 -->

3.  連携した攻撃を説明するときは、JTAC は、各 CAS brief の備考の部分で “Hold all readbacks” と述べてよい。そうすると、JTAC は、復唱を受ける前に、すべての element への brief を送信する。そのあと JTAC は、準備ができたら復唱を求める。各 element への攻撃の brief の直後に復唱を受けるほうが JTAC/FAC(A) の習慣に合うなら、そうしてもよい。

4.  第三者によるレーザー照射（Third-Party Lasing）。LGW を撃つのに、搭載していない（off-board）element を使うときは、JTAC は、Line 7 で、照射する側の call sign と、使う兵器のレーザー PRF 符号を示す。ほかの element にレーザーを提供する off-board のプラットフォームには、すべての関係者の詳細な調整が要る。FW と RW の照射のテンプレートは、下の図 V-7 と図 V-8 にある。JTAC は、照射するプラットフォームとの照合（correlation）も確実に行う。
